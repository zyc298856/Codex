# 五分钟成果演示讲稿

这份讲稿用于答辩当天的“成果演示约 5 分钟”。推荐顺序是先展示实时摄像头链路，再准备固定视频作为备选。现场演示时不要一开始就切换到 RGA、zero-copy 或多 context 激进配置，先保证老师能稳定看到“摄像头输入、板端识别、带框输出、电脑端观看”这条主链路。

## 演示前准备

板端先进入演示目录：

```bash
cd /home/ubuntu/eclipse-workspace/eclipse-workspace/Thesis\ Project/defense_demo
bash scripts/check_board_ready.sh
```

启动稳定实时方案：

```bash
bash scripts/run_live_safe.sh
```

电脑端用播放器打开：

```text
rtsp://<board-ip>:8554/drone
```

如果现场目标比较难检出，再切换更灵敏方案：

```bash
bash scripts/run_live_sensitive.sh
```

如果摄像头、网络或光照临时不稳定，切换固定视频备选：

```bash
bash scripts/run_video_backup.sh /home/ubuntu/public_videos/video01.mp4
```

## 0:00-0:40 展示目标

屏幕上先打开电脑端 RTSP 实时画面，让老师看到这不是离线截图，而是板端实时输出的视频流。

建议表述：

> 这里演示的是部署在 RK3588 开发板上的实时目标检测系统。摄像头画面先进入开发板，程序在板端调用 RKNN Runtime 和 NPU 完成推理，然后在画面中绘制检测框和告警条，最后通过 RTSP 推送到电脑端显示。也就是说，电脑只是观看端，核心检测过程是在 RK3588 上完成的。

## 0:40-2:00 稳定实时检测

拿手机显示无人机图片或视频，先保持中等距离和较慢移动速度，让检测框稳定出现。此时强调稳定配置的取舍。

建议表述：

> 现场演示默认使用的是 FP RKNN 稳定基线方案，置信度阈值设为 0.24，每 3 帧执行一次完整检测，中间帧通过轻量运动预测和框平滑维持显示连续性。这样做不是追求最高 NPU 吞吐率，而是为了让实时观看时画面更稳定、延迟更低。动态 ROI 和多 context 在这个主方案里没有默认打开，因为手持目标移动时它们反而可能带来裁剪漂移或调度抖动。

## 2:00-3:10 移动与自动变焦策略

先左右、上下移动手机，再前后移动。移动速度从慢到中等，不要一开始快速晃动。重点观察检测框、告警条和画面缩放响应。

建议表述：

> 这里可以看到，目标位置变化时，检测框会跟随目标移动；目标前后距离变化时，系统会根据目标框大小调整缩放策略。为了避免画面频繁抽动，变焦控制加入了死区、步进限制和冷却时间。对焦部分目前更偏向固定焦距和手动控制，因为连续自动对焦容易造成画面“呼吸”，会影响检测框稳定性。

## 3:10-4:10 告警与日志

指向画面上方的 `UAV ALERT` 告警条。如果现场方便，也可以打开输出目录中的 CSV/日志文件说明。

建议表述：

> 当系统检测到无人机目标后，会在画面顶部显示告警条，同时记录目标数量、最高置信度和检测事件。任务书中提到的报警闭环，在本文中先用画面 Overlay 和事件日志完成软件层验证。这样做适合答辩现场演示，也避免了没有外接继电器或蜂鸣器时无法展示闭环的问题。后续如果接入 GPIO，只需要把当前事件接口连接到外设控制层即可。

## 4:10-5:00 备选结果与工程结论

如果实时链路顺利，可以不切换；如果现场网络、光照或手机画面影响检测，就播放固定视频备选结果。若老师问到硬件最优链路，再说明路线 B。

建议表述：

> 如果现场实时输入受到光照、网络或手持移动影响，我还准备了公开无人机视频的固定输入验证。固定视频的优点是可重复、可对比，适合说明模型在真实无人机场景下能够产生有效检测框。除了这条稳定演示链路，我还做了 RGA、hybrid INT8、zero-copy 和 MPP 解码到 RGA 的路线 B 探索。路线 B 更接近硬件最优方向，但答辩现场优先展示稳定方案，激进链路作为技术储备和后续优化方向。

## 现场取舍口径

- 如果老师问“为什么不用多 context 做主方案”：多 context 更适合逐帧检测吞吐实验，但实时观看更关心端到端延迟和画面稳定。
- 如果老师问“为什么 RGA/zero-copy 没放到主演示”：这些路径已经完成阶段性验证，但现场主方案要优先保证稳定；激进链路适合说明后续性能上限。
- 如果老师问“为什么 INT8 不是默认方案”：full INT8 出现过置信度塌缩，hybrid INT8 能恢复检测，但端到端收益还不如 FP 稳定，因此演示采用 FP RKNN。
- 如果老师问“为什么不用连续自动对焦”：连续对焦会引入焦点呼吸，目标框会随清晰度波动。演示中更适合使用固定焦距或受控对焦。
