# 2026-05-12 教室演示方案：远距离无人机图像实时识别

本文档用于毕业答辩前的教室演示准备。目标不是替换论文中的正式实验，而是把已经完成的 RK3588 + USB 摄像头 + RKNN + RTSP 链路整理成一套低风险、可复现、可解释的现场展示流程。

## 1. 演示目标

在教室环境中，用 USB 摄像头拍摄距离约 5-10 m 的无人机图片目标，通过 RK3588 板端程序完成实时检测，并在电脑端通过 RTSP 观看带框画面。

演示要让老师直观看到：

- 摄像头实时采集画面；
- RK3588 板端调用 NPU 推理；
- 画面中出现 `drone` 检测框和 `UAV ALERT` 软件报警条；
- 目标较小时，摄像头可通过光学变焦改善目标尺寸；
- 系统不是单张图片离线识别，而是一条实时视频链路。

## 2. 不改变稳定成果的原则

本方案只作为演示配置，不覆盖已有稳定模型和论文实验结果。

- 默认模型仍使用 FP RKNN 稳定模型；
- 不把 smoke 训练权重替换为正式演示权重；
- 不默认启用 dynamic ROI，避免 ROI 裁剪导致检测框偏移；
- 不默认启用 multi-context，避免现场演示时引入调度延迟；
- 不默认启用 full INT8，避免小目标置信度不稳定。

## 3. 推荐演示材料

### 3.1 目标图片

优先使用打印图片，而不是手机屏幕。

- 推荐尺寸：A3 优先，A2 更稳；
- 图片内容：无人机主体清楚、背景干净、轮廓对比明显；
- 图片数量：至少准备 3 张；
- 推荐类型：近景无人机、中景无人机、小目标无人机。

手机屏幕也可以作为补充演示，但不建议作为唯一目标。手机屏幕容易出现反光、过曝、摩尔纹和刷新频闪，10 m 距离下会明显降低检测稳定性。

### 3.2 教室位置

建议提前在地面或桌面标出三个距离点：

- 5 m：保底演示点，优先保证一定能识别；
- 8 m：较接近正式展示距离；
- 10 m：挑战展示点，用于说明小目标和光学变焦的作用。

如果 10 m 处检测不稳定，答辩时不要硬撑。可以先在 5-8 m 稳定展示，再移动到 10 m 说明远距离小目标识别的难点和系统取舍。

## 4. 推荐运行配置

### 4.1 稳定优先配置

适合正式答辩演示，目标是画面稳定、检测框不明显跳动。

```bash

RK_YOLO_BOX_SMOOTH=1 \
RK_YOLO_BOX_SMOOTH_ALPHA=0.35 \
RK_YOLO_BOX_SMOOTH_IOU=0.05 \
RK_YOLO_TRACK_MODE=motion \
RK_YOLO_CAMERA_FOCUS_AUTO=0 \
RK_YOLO_CAMERA_FOCUS=260 \
RK_YOLO_AUTO_ZOOM=1 \
RK_YOLO_AUTO_ZOOM_MIN=0 \
RK_YOLO_AUTO_ZOOM_MAX=70 \
RK_YOLO_AUTO_ZOOM_STEP=6 \
RK_YOLO_AUTO_ZOOM_COOLDOWN=18 \

./rk_yolo_live_rtsp \
```

电脑端观看：

```text
rtsp://192.168.10.186:8554/drone
```

说明：

- `score=0.24` 是当前演示较稳的折中值；
- `dynamic_roi=0` 用于避免 ROI 裁剪坐标还原误差造成框偏移；
- `detect_every_n=3` 用于降低 NPU 调用频率，提升实时观看连续性；
- `box_smooth` 用于减少相邻帧检测框突变；
- `auto_zoom` 用于让小目标逐步占据更合适的画面比例。

### 4.3 不建议现场默认开启的配置

| 配置 | 不默认开启的原因 |
|---|---|
| `RK_YOLO_DYNAMIC_ROI=1` | 目标移动和变焦叠加时，ROI 坐标还原更容易造成框偏移 |
| `RK_YOLO_INFER_WORKERS=2` | 多 context 更适合吞吐实验，实时观看时可能引入调度延迟 |
| full INT8 RKNN | 小目标置信度曾出现塌缩，不适合作为现场默认方案 |
| `RK_YOLO_TRACK_MODE=optflow` | 快速移动或手机屏幕反光时，光流特征点可能不稳定 |
| 自动对焦持续开启 | 画面容易出现“呼吸感”，导致检测框和清晰度反复波动 |

## 5. 5 分钟成果演示流程

### 0:00-0:40 准备说明

展示板子、USB 摄像头、电脑端 RTSP 播放窗口。

推荐说法：

> 这里演示的是 RK3588 板端实时检测链路。摄像头画面先进入板端程序，经过预处理和 RKNN NPU 推理后，检测结果会画到视频帧上，再通过 RTSP 推送到电脑端观看。

### 0:40-1:40 近距离稳定识别

把无人机打印图放在 5 m 左右，先保证检测框稳定出现。

观察点：

- 是否显示 `drone` 框；
- 是否出现 `UAV ALERT`；
- 框是否明显跳动；
- 电脑端画面是否有明显延迟。

### 1:40-2:50 中远距离识别

把目标移动到 8-10 m，保持背景干净。

推荐说法：

> 远距离时目标在画面中占比下降，检测难度会明显增加。因此系统里加入了光学变焦控制和框平滑策略，目标是尽量保证画面连续，而不是只追求每一帧都完整检测。

### 2:50-3:50 自动变焦展示

让目标保持较小，观察摄像头逐步变焦。

注意：

- 不要快速左右晃动目标；
- 先让目标稳定 3-5 秒；
- 如果变焦后框消失，可以把目标稍微移回画面中心。

推荐说法：

> 这里的变焦不是重新训练模型，而是根据检测框大小调整 UVC 摄像头的光学变焦值，让小目标在画面中占据更合适的比例。

### 3:50-4:40 移动目标展示

用打印图或手机屏幕做轻微移动：

- 左右移动：幅度小一些；
- 上下移动：不要离开画面中心太远；
- 前后移动：速度不要太快；
- 每次移动后停顿 1-2 秒。

推荐说法：

> 检测间隔和轻量跟踪用于在非关键帧中保持框的连续性，框平滑用于降低相邻帧之间的突变。快速运动时仍可能出现短暂丢框，这是小目标检测和实时视频链路共同造成的限制。

### 4:40-5:00 总结

推荐说法：

> 这套演示重点验证了从摄像头输入、RK3588 NPU 推理、检测框绘制、软件报警到 RTSP 输出的完整链路。为了保证现场稳定性，最终演示采用 FP RKNN 模型和低延迟策略；RGA、INT8 和多 context 作为论文中的硬件优化与对比实验保留。

## 7. 备用方案

### 7.1 现场摄像头不稳定

切换到固定视频 RTSP replay：

```bash
RK_YOLO_INPUT_LOOP=1 \
RK_YOLO_DYNAMIC_ROI=0 \
RK_YOLO_BOX_SMOOTH=1 \
./rk_yolo_live_rtsp \
  /home/ubuntu/public_videos/video01.mp4 \
  ../../training_runs/drone_gpu_50e/weights/best.end2end_false.op12.rk3588.fp.v220.rknn \
  /drone 640 480 15 0.24 0.45 8554 3
```

解释口径：

> 固定视频用于保证输入源可重复，便于比较不同配置；实时摄像头则用于展示真实部署链路。两者使用同一套检测和推流程序。

### 7.2 远距离目标不稳定

切回 5-8 m，并说明：

> 10 m 场景下，如果目标在图像中只剩很少像素，检测稳定性会明显下降。实际系统中通常需要更高焦距镜头、更高分辨率输入或针对远距离小目标补充训练样本。

### 7.3 误检偏多

从 `score=0.20` 切回 `score=0.24` 或 `0.30`。

解释口径：

> 阈值越低越灵敏，但误检风险越高；阈值越高越保守，但小目标可能漏检。演示中根据目标距离选择折中值。

## 8. 答辩可能被问到的问题

### Q1：为什么不用真实无人机？

答：

真实无人机飞行涉及场地、安全和低空飞行管理限制。本文用打印图、公开视频和室内实时摄像头演示，主要验证算法部署和实时视频链路。固定视频保证可重复，摄像头演示验证实时输入输出链路。

### Q2：为什么用 FP 模型，而不是 INT8？

答：

full INT8 在小目标无人机场景中出现过置信度塌缩，hybrid INT8 能恢复检测能力，但端到端性能优势还不稳定。为了保证现场展示稳定性，演示采用 FP RKNN 稳定模型；INT8 作为量化优化实验写入论文。

### Q3：为什么不开 multi-context？

答：

multi-context 能提升逐帧检测吞吐，但实时观看更关注端到端延迟和画面连续性。当前演示采用检测间隔、轻量跟踪和框平滑，延迟更可控。

### Q4：为什么关闭 dynamic ROI？

答：

ROI 对固定视频和部分场景有加速潜力，但在摄像头实时演示中，变焦、目标移动和 ROI 坐标还原叠加后更容易造成框偏移。为了现场稳定性，演示默认关闭 dynamic ROI。

### Q5：自动变焦和自动对焦是否都已经完成？

答：

当前已完成基于检测框大小的 UVC 光学变焦控制，并验证摄像头支持相关控制项。对焦方面，现场演示更推荐使用固定手动焦距或低频调整，避免连续自动对焦造成画面呼吸和检测抖动。后续可进一步做基于清晰度评价的闭环对焦策略。
