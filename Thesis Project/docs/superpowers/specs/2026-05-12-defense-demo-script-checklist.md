# 2026-05-12 答辩 5 分钟成果演示讲稿与操作清单

本文档用于毕业答辩现场的“成果演示约 5 分钟”部分。目标是让演示过程简洁、稳定、可解释，避免临场因为参数、网络或摄像头状态混乱而影响展示效果。

## 1. 演示定位

本演示展示的是一套已经部署到 RK3588 开发板上的无人机目标检测系统。系统从 USB 摄像头获取实时画面，在板端调用 RKNN Runtime 与 NPU 完成检测，然后将带检测框和报警条的画面通过 RTSP 推送到电脑端观看。

演示重点不是证明算法在所有真实无人机场景下都达到最高精度，而是证明：

- 模型已经从训练权重迁移到 RKNN 格式；
- 检测程序已经能在 RK3588 板端运行；
- 视频输入、NPU 推理、后处理、画面叠加和 RTSP 输出形成了完整链路；
- 系统支持检测间隔、框平滑、轻量跟踪和摄像头光学变焦等实时演示策略；
- 在教室条件下可以用远距离无人机图片模拟小目标检测场景。

## 3. 演示讲稿

### 0:00-0:30 开场

建议讲稿：

> 老师好，下面我演示本文完成的 RK3588 板端无人机目标检测系统。这里使用 USB 摄像头作为实时输入，检测程序运行在 RK3588 开发板上，模型是已经转换成 RKNN 格式的单类无人机检测模型。检测结果会叠加到视频帧上，并通过 RTSP 推送到电脑端实时观看。

操作：

- 确认电脑端已打开 RTSP 播放窗口；
- 摄像头对准 5 m 左右的无人机打印图；
- 确认画面中有 `UAV ALERT` 或检测框。

### 0:30-1:20 近距离稳定检测

建议讲稿：

> 先看近距离目标。系统在每个关键帧调用 NPU 推理，后处理模块会把模型输出解析成检测框。如果检测到无人机，画面顶部会出现报警条，并显示目标数量和最大置信度。

操作：

- 保持目标静止 3-5 秒；
- 让老师看到 `drone` 框和顶部报警条；
- 如果框偶尔消失，不要急着移动目标，先等待 1-2 秒。

可补充说明：

> 这里使用的是 FP RKNN 稳定模型，主要目的是保证现场展示的检出率和稳定性。INT8 量化在论文中做了实验，但由于小目标场景下存在置信度下降问题，所以没有作为默认演示方案。

### 1:20-2:20 中远距离检测

建议讲稿：

> 接下来把目标放远一些，模拟教室里较远距离的小目标识别。距离变远后，无人机在画面中只占较小区域，检测难度会明显上升。为了适应这种情况，系统采用较低的检测阈值，并结合框平滑来减少显示抖动。

操作：

- 将目标移动到 8 m 或 10 m 附近；
- 如果 10 m 不稳定，先退回 8 m；
- 保持背景尽量干净，不要让目标贴近强反光区域。

可补充说明：

> 这个演示不是简单识别一张图片，而是通过实时摄像头输入验证完整视频链路。远距离小目标本身就是无人机检测的难点，因此我在论文里也把误检、漏检和小目标尺度作为重点分析内容。

### 2:20-3:20 自动变焦展示

建议讲稿：

> 当目标在画面中占比太小时，系统可以根据检测框大小调整 UVC 摄像头的光学变焦。这里的控制逻辑是：如果检测框面积比例低于设定范围，就逐步放大；如果目标过大或长时间丢失，则适当回退。这样做的目的是让小目标在输入画面中占据更合适的比例。

操作：

- 保持目标较小并位于画面中心附近；
- 等待摄像头变焦动作；
- 观察目标尺寸变化和检测框变化；
- 不要在变焦过程中快速晃动目标。

可补充说明：

> 当前自动变焦已经完成策略验证和板端测试。自动对焦方面，为了避免连续对焦造成画面呼吸和检测框波动，现场演示更推荐使用固定手动焦距或低频调整。

### 3:20-4:20 轻微移动目标

建议讲稿：

> 现在简单移动一下目标。实时系统不能只看单次推理速度，还要看画面是否连续、延迟是否可控。这里使用检测间隔策略，不是每一帧都调用 NPU，而是在中间帧使用轻量运动预测保持检测框连续，同时用框平滑减少相邻帧之间的突变。

操作：

- 先慢速左右移动；
- 再轻微上下移动；
- 最后做一次小幅前后移动；
- 不建议快速甩动目标，避免目标离开画面或出现运动模糊。

可补充说明：

> 如果目标快速移动或者画面模糊，检测框短暂消失是正常现象。这也是后续需要通过更多运动模糊样本和真实场景数据继续提升的部分。

### 4:20-5:00 总结

建议讲稿：

> 总结一下，这套演示验证了从摄像头输入、RK3588 NPU 推理、检测结果绘制、软件报警到 RTSP 输出的完整运行流程。为了保证现场稳定性，最终演示采用 FP RKNN 模型、检测间隔、框平滑和自动变焦策略。论文中还对 RGA、INT8、multi-context 和 zero-copy 等硬件优化路径做了实验分析，这些内容主要用于说明系统优化过程和工程取舍。

收尾动作：

- 停留在有检测框的画面；
- 不要立刻关闭程序；
- 等老师提问。

## 5. 现场异常处理

### 5.1 电脑端看不到 RTSP

检查顺序：

1. 确认程序正在运行；
2. 确认电脑和板子在同一网络；
3. 确认 IP 是当前地点的板子 IP；
4. 确认 RTSP 地址是 `rtsp://192.168.10.186:8554/drone`；
5. 重新打开播放器；
6. 如果仍不行，切换到备用固定视频演示。

### 5.2 检测框不出现

处理顺序：

1. 先把目标移回 5 m；
2. 让目标位于画面中心；
3. 避免反光和过曝；
4. 降低阈值到 `0.20`；
5. 使用更大的打印图；
6. 切换到备用公开视频演示。

### 5.3 检测框跳动

处理顺序：

1. 确认 `RK_YOLO_DYNAMIC_ROI=0`；
2. 确认 `RK_YOLO_BOX_SMOOTH=1`；
3. 确认 `RK_YOLO_TRACK_MODE=motion`；
4. 不要使用 `optflow`；
5. 降低目标移动速度；
6. 避免摄像头持续自动对焦。

### 5.4 误检偏多

处理顺序：

1. 把阈值从 `0.20` 调回 `0.24`；
2. 如果仍误检，调到 `0.30`；
3. 减少背景杂物；
4. 不要用复杂纹理背景。

如果现场紧张，可以直接按下面这段说：

> 本系统运行在 RK3588 开发板上，摄像头采集到的视频先进入 C++ 实时处理程序，随后调用 RKNN Runtime 在 NPU 上完成无人机检测。检测结果经过后处理后叠加到画面中，并通过 RTSP 推送到电脑端观看。为了保证现场实时性，系统没有每一帧都完整检测，而是采用检测间隔、轻量运动预测和框平滑策略，降低端到端延迟并减少检测框抖动。对于远距离小目标，系统还加入了基于检测框大小的 UVC 光学变焦控制。最终演示采用 FP RKNN 稳定模型，INT8、RGA 和多 context 作为论文中的硬件优化实验进行对比分析。
