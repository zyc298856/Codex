# 毕业设计周记（学校系统日期版）

题目：基于嵌入式平台的目标检测系统研究

说明：以下按学校系统截图中最新 14 个周记时间段整理，可逐条复制到网页表单。

## 第1周（2025-12-29 ? 2026-01-04）：明确课题目标与任务边界

本周主要重新阅读任务书和开题报告，明确本课题不是只验证 YOLO 模型能否识别无人机，而是要把已训练模型迁移到 RK3588 平台，并形成视频采集、预处理、NPU 推理、后处理和结果输出的完整链路。我把任务拆成模型转换、板端运行、实时视频显示、硬件优化和论文记录几条线，后续工作也按这些方向推进。

## 第2周（2026-01-05 ? 2026-01-11）：整理模型文件与转换路线

本周整理了项目中的 YOLOv10、ONNX 和单类无人机检测模型文件，初步确定采用 best.pt -> best.onnx -> best.rk3588.fp.rknn 的转换路线。整理过程中发现，模型来源、输入尺寸、导出参数和输出张量格式都需要单独记录，否则后续在 RKNN 端出现问题时很难判断是模型本身、导出方式还是后处理逻辑不匹配。

## 第3周（2026-01-12 ? 2026-01-18）：搭建转换环境并核对输出结构

本周在 PC/WSL 环境中搭建模型转换和初步测试环境，重点核对 ONNX 输出结构与后处理代码之间的对应关系。调试时发现，模型转换为 RKNN 并不代表一定能在板端稳定运行，输出张量结构必须和 C++ 后处理保持一致。因此我开始把单类别输出、置信度阈值和坐标还原逻辑作为后续排查重点。

## 第4周（2026-01-19 ? 2026-01-25）：配置 RK3588 板端运行环境

本周通过 SSH 连接 RK3588 开发板，检查 OpenCV、RKNN Runtime、GStreamer 等运行环境，并把程序验证路径分成固定视频和实时摄像头两类。固定视频便于重复测试同一输入，实时摄像头则更接近最终系统演示场景。这个阶段主要解决的是运行环境、路径、权限和依赖库问题，为后续板端推理做准备。

## 第5周（2026-03-02 ? 2026-03-08）：完成 RKNN 固定视频验证

本周对无人机 RKNN 模型进行板端验证。早期模型在 rknn_run 阶段曾出现异常，后来通过调整 ONNX 导出方式为 end2end=False，并让输出保持为 1 x 5 x 8400 后，C++ 后处理能够正确解析候选框。固定公开视频测试中已经能够生成带框视频和逐帧 CSV 记录，这说明模型迁移链路基本建立起来了。

## 第6周（2026-03-09 ? 2026-03-15）：接入 USB 摄像头与 RTSP 显示

本周把输入从固定视频推进到 USB 摄像头，并通过 RTSP 在电脑端查看带框画面。实际测试中发现，实时链路不仅要关注 NPU 推理时间，还要关注采集、编码、推流和电脑端播放带来的延迟。为避免只看单帧推理时间造成误判，我开始记录 stream_fps、npu_fps、端到端延迟和资源占用等指标。

## 第7周（2026-03-16 ? 2026-03-22）：构建多线程实时处理流水线

本周将程序改成采集、推理和输出相互解耦的多线程结构，并引入有界队列控制积压。采集线程持续写入最新帧，推理线程按当前策略决定是否调用 NPU，输出线程负责绘制检测结果并推送视频流。后续测试中，detect_every_n=3 的策略在实时观看效果和 NPU 调用频率之间取得了比较稳的折中。

## 第8周（2026-03-23 ? 2026-03-29）：加入框平滑、轻量跟踪与动态 ROI

本周针对检测框左右抖动和跳帧后的显示不连续问题，加入框平滑、运动预测和轻量光流跟踪。运动预测根据相邻检测框中心位移估计目标位置，光流模式则利用特征点位移辅助判断。动态 ROI 也进行了尝试，但在某些场景下会带来定位偏移，因此后续默认配置更偏向稳定的框平滑和运动预测。

## 第9周（2026-03-30 ? 2026-04-05）：开展 NPU 多 context 推理实验

本周根据导师提出的 NPU 多线程方向，加入多 context 推理机制，比较单 context 和双 context 在逐帧检测场景下的表现。实验表明，多 context 可以提升每帧检测时的 NPU 吞吐能力，但 worker 数继续增加后会带来调度和输入设置开销。由此我认识到，实时演示不能只追求 npu_fps，还要看端到端延迟和画面稳定性。

## 第10周（2026-04-06 ? 2026-04-12）：验证 RGA 硬件预处理路径

本周实现并验证 RGA 预处理路径，包括 BGR 到 RGB 转换、resize 和 letterbox 等操作，并通过 RK_YOLO_REQUIRE_RGA=1 强制检查是否真正调用 RGA。板端结果说明 RGA 路径能够完成端到端验证，但在当前 OpenCV 读帧后的内存路径下，数据搬运和映射开销会抵消部分硬件收益。后续若要进一步提升，需要推进 MPP、RGA 与 NPU 的零拷贝链路。

## 第11周（2026-04-13 ? 2026-04-19）：推进 INT8 量化实验

本周重点尝试 full INT8 和 hybrid INT8 量化模型。full INT8 模型虽然可以完成转换和加载，但公开视频测试中置信度明显下降，难以稳定产生有效检测框。随后采用保护输出 Sigmoid 至最终输出层的 hybrid INT8 方案，检测结果有所恢复，但端到端速度并没有稳定优于 FP RKNN。因此，系统演示仍采用 FP RKNN 稳定基线方案。

## 第12周（2026-04-20 ? 2026-04-26）：实现软件报警与摄像头控制验证

本周根据任务书中的报警闭环要求，实现软件层面的报警 Overlay 和 alarm_events.csv 事件记录。由于暂时没有继电器或蜂鸣器，物理报警先用画面提示和日志替代。同时使用 v4l2-ctl 检查 USB 摄像头暴露的 UVC 控制项，并对自动对焦、变焦控制和基于检测框的控制策略做了板端验证，为后续演示中的镜头控制做准备。

## 第13周（2026-04-27 ? 2026-05-03）：整理论文、图表与检测结果材料

本周主要整理毕业论文和实验材料。论文中对系统设计、板端实现、实验结果和硬件优化边界进行了补充，并根据导师意见合并部分小章节，减少二级标题数量。与此同时，我整理了公开视频和摄像头演示中的带框截图，用于说明模型在不同场景下的检测效果，也补充了中文参考文献，增强论文的文献支撑。

## 第14周（2026-05-04 ? 2026-05-10）：形成教师检查版并准备答辩演示

本周围绕最终提交和答辩演示做收尾工作。论文已根据导师意见完成章节合并、图表检查和参考文献核对；系统侧继续调整摄像头实时检测、框平滑、置信度阈值和变焦策略，使教室演示时画面尽量稳定。后续答辩中需要重点说明 FP 稳定方案、RGA 阶段性验证、hybrid INT8 结果以及为什么最终选择更稳的实时配置。
